Colore LED Stato Sistema

Gestione Allarmi
  • AlarmHandler – std::set<AlarmType> gestisce allarmi multipli senza duplicati; nextAlarm() cicla tra i colori LED attivi; supporta ack per-allarme
  • HandleExceptions – validazione centralizzata: handleMqttExceptions() verifica nome pianta, handleThresholds() confronta letture con soglie, handleInfluxException() controlla connessione, handleDataException() valida dati sensore, handleConnectionException() verifica RSSI WiFi; handleSuccess() resetta tutti gli allarmi
Servizi Aggiuntivi
  • WeatherService – geolocalizza città via Open-Meteo geocoding API, recupera previsioni meteo, invia codice previsione su Telegram; ottimizzato per RAM ESP8266
  • TelegramNotifier – sendNotification() per allarmi generic, sendWeatherAlert() per previsioni meteo con codice e città
  • LCDHandler – coda std::deque con messaggi tipo DATA, ERROR, INFO; popAndDisplay() mostra il prossimo messaggio; addMessagePlantData() formatta letture sensore
Sensori & Comunicazione
  • SensorManager – getAllData() restituisce struct PlantData (temperatura, umidità, luce, validità); legge DHT11 + fotoresistenza KY-018
  • MqttHandler – begin(), handle(), reconnect(); espone getThresholds(), getSettings(), isRunning(), isStandBy(); gestisce azioni differite con handleDeferredActions()
Infrastruttura
  • InfluxHandler – sendDataToInflux() con RSSI e soglie; isReadyToWrite() con intervallo configurable via updateInterval(); ticker per write periodiche
  • WiFiHandler (static) – begin() con WiFiManager per auto-connect; getRSSI(), getMacAddress() per ID univoco; resetCredentials() per reset WiFi

SecurityESP – Sicurezza Fisica

🚪 Rilevamento Porta
  • Sensore digitale su D1
  • Pubblica evento apertura/chiusura via MQTT
  • Registra evento su InfluxDB (misurazione DoorAlarm)
  • Conta aperture giornaliere
🔥 Rilevamento Fiamma
  • Doppio check: sensore fiamma (D2) + NTC (A0)
  • Allarme solo se fiamma rilevata ET T > 30°C
  • Buzzer su D3 come allarme acustico
  • Notifica Telegram immediata
  • Misurazione InfluxDB: FlameAlarm
SecurityESP.ino
├─ WiFiHandler
│    → autoConnect + NTP clock sync
├─ MqttHandler
│    → publish door/flame events
├─ InfluxHandler
│    → DoorAlarm + FlameAlarm measurements
├─ TelegramNotifier
│    → alert fiamma su Telegram
└─ loop() @ 500ms
     → checkDoor() + checkFlame()
Il SecurityESP pubblica sul topic lab_iot/mafogani/connection con tipo SECURITY_SENSOR. Il server risponde con la lista topic appropriata.
05

Comunicazione MQTT

Node Discovery – l'ESP si announce con tipo (PLANT_SENSOR / SECURITY_SENSOR), il server risponde con i topic dinamici appropriati.
Topic connessione (LWT + retain): 
lab_iot/mafogani/connection/{ESP_ID}
  → {id, status: CONNECTING|ONLINE|OFFLINE, type}
Topic statico (subscribe all'avvio): 
lab_iot/mafogani/topics
  → imposta dinamicamente i topic da sottoscrivere
Topic dinamici (subscribe dopo ricezione topics): 
lab_iot/mafogani/threshold
  → soglie pianta (JSON)
lab_iot/mafogani/start-stop
  → comandi START / STOP
lab_iot/mafogani/set-mcu
  → settings ESP (nome, backup, timer, location)
lab_iot/mafogani/backup
  → standby / wake-up per failover
lab_iot/mafogani/security
  → eventi sicurezza (door/flame) → WebSocket
Payload threshold (esempio): 
{
  "id": "ESP_ID",
  "name": "monstera_albo",
  "thresholds": {
    "temp":  { "min": 18, "max": 27 },
    "hum":   { "min": 60, "max": 75 },
    "light": { "min": 300,"max": 500}
  }
}
Payload MCU settings (esempio): 
{
  "id": "ESP_ID",
  "name": "Nodo Serra",
  "backup": false,
  "timer": 10,
  "location": "Serra Est"
}
Backup Failover
  • Nodi accoppiati (main + backup stesso nome)
  • Main OFFLINE → backup si risveglia da standby
  • Main torna ONLINE → backup torna in standby
QOS = 1  ·  LWT su connection topic  ·  retain su stati

Telegram Bot & API Integrate

🤖 Bot WebApp – Comandi
  • /start – Lista nodi → avvia ESP
  • /stop – Lista nodi → ferma ESP
  • /syncplant – Nodo → pianta → sync soglie MQTT
  • /plantdata – Pianta → sensore → intervallo → grafico matplotlib PNG
  • /plantlast – Pianta → report ultimo lettura
Bot WebApp: python-telegram-bot con inline keyboard, avviato nel lifespan di FastAPI, accede a SQLite + InfluxDB. Bot Firmware: TelegramNotifier sull'ESP8266 con sendMessage Markdown. Condividono lo stesso token.
🌤️ Open-Meteo API (gratuita, no key)
  • Geocoding – /v1/search?name={city}&count=1 → lat/lon città
  • Forecast – /v1/forecast?lat={lat}&lon={lon}&daily=weather_code&forecast_days=1 → WMO weather code
WeatherService sull'ESP8266: geolocalizza città → recupera previsione → invia alert meteo via Telegram. JSON scope limitato per RAM.

Conclusioni

Il progetto Greenhouse Monitor dimostra come un sistema IoT completo possa essere realizzato con hardware a basso costo, coprendo dall'edge al cloud con un'unica stack coerente.
Realizzazione
  • Sistema di monitoraggio ambientale continuo (temperatura, umidità, luce) con 3 piante e soglie indipendenti
  • Sicurezza fisica con rilevamento porta e fiamma, doppio check NTC, buzzer e notifica Telegram immediata
  • Due nodi ESP8266 indipendenti con ruoli dedicati (serra + sicurezza)
  • Backup failover automatico: quando il nodo principale va offline, il backup si risveglia
  • Dashboard web completa con vista piante e vista sicurezza, grafici storici e controllo remoto
  • Bot Telegram per controllo totale da smartphone con grafici generati on-the-fly
Sfide Affrontate
  • Ottimizzazione RAM su ESP8266: scope JSON limitato, memoria gestita manualmente
  • Gestione connessioni concorrenti: MQTT + WiFi + HTTP + InfluxDB su microcontrollore
  • Coerenza dati in tempo reale tra MQTT, InfluxDB, WebSocket e Telegram
  • Architettura modulare firmware: ogni responsabilità in una classe separata
Stack Completo
  • Edge – ESP8266 × 2, sensori analogici/digitali, attuatori (LED, LCD, buzzer)
  • Firmware – Arduino C++, 9 moduli OOP, WiFiManager, Ticker
  • Comunicazione – MQTT pub/sub con LWT, QoS 1, node discovery
  • Backend – FastAPI, SQLite (config), InfluxDB (time-series), WebSocket
  • Frontend – HTML + Tailwind CSS + JS vanilla + Chart.js
  • Integrazioni – Telegram Bot, Open-Meteo API, matplotlib
Possibili Evoluzioni
  • Deep sleep per risparmio energetico e nodi a batteria
  • Notifiche push / e-mail per allarmi non critici
  • Nodi aggiuntivi: irrigazione automatica, pH suolo, ventole
  • Reclamo piante interattivo via Telegram con consigli di cura
  • Storico allarmi con statistiche e trend sulla dashboard
